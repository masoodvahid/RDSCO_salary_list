# سامانه آنلاین مدیریت لیست حقوق و دستمزد

سامانه آنلاین تکمیل و تایید لیست حقوق ماهانه، با ظاهر و رفتار شبیه اکسل و خروجی PDF.
منابع انسانی لیست حقوق ماه را می‌سازد، پروژه‌ها مقادیر پرسنل خودشان را وارد می‌کنند، و لیست هر پروژه با کد پیامکی (کاوه‌نگار) مرحله‌به‌مرحله تایید می‌شود.

**Stack:** Laravel 13 · Livewire 4 · MySQL 8 · Tailwind 4 · Vazirmatn (self-hosted) · OpenSpout (Excel)

---

## روند کار

| مرحله | چه کسی | چه اتفاقی |
|---|---|---|
| ۱. آماده‌سازی | مدیر | ساخت لیست حقوق ماه (یا کپی از ماه قبل)، پروژه‌های ماه، ستون‌ها و قفل ستون‌ها، ورود پرسنل از اکسل، انتخاب پروژه هر نفر، مهلت تکمیل، دعوت افراد |
| ۲. تکمیل | ویرایشگر پروژه | ورود مقادیر در ستون‌های باز، فقط برای پرسنل پروژه خودش و تا پایان مهلت |
| ۳. تایید پروژه | تاییدکننده پروژه (مدیر پروژه) | تایید با کد پیامکی |
| ۴. بررسی و تایید منابع انسانی | مدیر | تایید/رد هر رکورد با یادداشت، اصلاح مقادیر، تایید با کد پیامکی |
| ۵. تایید مالی | تاییدکننده روی همه پروژه‌ها (مالی) | تایید/رد هر رکورد، تایید نهایی با کد پیامکی |
| — | مشاهده (مثلاً مدیرعامل) | دیدن زنده همه مراحل و گذاشتن یادداشت |

- **رد رکورد توسط منابع انسانی:** لیست آن پروژه به مرحله «در حال تکمیل» برمی‌گردد و تاییدهای قبلی باطل می‌شود.
- **رد رکورد توسط مالی:** لیست به منابع انسانی برمی‌گردد.
- **هر تایید یک امضاست:** زمان، IP و کد پیامکی ثبت می‌شود، به‌علاوه‌ی SHA-256 داده‌ای که دقیقاً تایید شده است.
  - کد پیامکی به همان hash گره خورده است. اگر بین ارسال کد و وارد کردن آن داده تغییر کند، تایید انجام نمی‌شود.
  - اگر مدیر بعد از یک تایید عددی را عوض کند، کنار آن امضا «تغییر پس از تایید» نمایش داده می‌شود.
- **ثبت تغییرات:** هر تغییر خانه، ردیف، ستون و مرحله در `change_logs` ثبت می‌شود.
- **یادداشت‌ها:** همه‌ی نقش‌ها (حتی مشاهده) روی ردیف یادداشت می‌گذارند. فقط مدیر می‌تواند یادداشت را حذف کند؛ متن و نویسنده‌ی یادداشت حذف‌شده در `change_logs` می‌ماند.

## کار با لیست حقوق

- **ذخیره‌ی خودکار:** هر خانه بعد از خروج یا Enter ذخیره می‌شود. اگر کسی هم‌زمان همان خانه را تغییر داده باشد، خانه نارنجی می‌شود و مقدار جدید او نمایش داده می‌شود.
- **جابه‌جایی:** با Enter و کلیدهای جهت.
- **چسباندن از اکسل:** چند خانه‌ی کپی‌شده از اکسل یک‌جا در لیست حقوق چسبانده می‌شوند.
- **ترتیب ستون‌ها:** مدیر سرستون را از دستگیره‌ی کنار عنوان می‌گیرد و جابه‌جا می‌کند. ترتیب جزو داده‌ی امضاشده نیست، پس امضاهای تایید را باطل نمی‌کند.
- **کپی به خانه‌های پایین (Fill handle):** مربع کوچک گوشه‌ی پایین خانه‌ی فعال را بگیرید و به بالا یا پایین بکشید تا مقدار در همان ستون کپی شود. خانه‌هایی که کاربر اجازه‌ی ویرایششان را ندارد رد می‌شوند و Esc وسط کشیدن کار را لغو می‌کند. `Ctrl+D` هم مقدار خانه‌ی بالایی را کپی می‌کند.
- **بازه‌ی مجاز ستون‌های عددی:** مدیر هنگام ساخت یا ویرایش ستون می‌تواند حداقل و/یا حداکثر تعیین کند؛ خالی یعنی بدون محدودیت.
  - مقدار خارج از بازه (یا متن در ستون عددی) ذخیره نمی‌شود: پیام خطا زیر همان خانه نمایش داده می‌شود، Enter خانه را برای اصلاح نگه می‌دارد و با Esc یا رفتن به خانه‌ی دیگر مقدار قبلی برمی‌گردد. ورود اکسل هم چنین مقداری را رد می‌کند.
  - اگر بازه بعداً تنگ‌تر شود، مقادیر فعلی دست نمی‌خورند و فقط با رنگ قرمز مشخص می‌شوند.

## نقش‌ها

نقش‌ها سلسله‌مراتبی‌اند: هر نقش اختیارات نقش قبلی را دارد به‌علاوه‌ی یک چیز.

| نقش | محدوده | اختیار |
|---|---|---|
| مشاهده | یک پروژه یا همه | دیدن، یادداشت |
| ویرایشگر | یک پروژه (الزامی) | ویرایش ستون‌های باز تا مهلت؛ بدون افزودن ردیف و تغییر ستون قفل |
| تاییدکننده | یک پروژه ← تایید پروژه · همه ← تایید مالی | + تایید با کد پیامکی |
| مدیر | همه | همه‌کار: ساختار، قفل ستون، ردیف‌ها، پروژه‌ها، اعضا، تایید منابع انسانی، بازگشایی |

- **یک تاییدکننده برای هر پروژه:** هر پروژه حداکثر یک تاییدکننده‌ی فعال دارد. این قید در خود دیتابیس اعمال می‌شود (unique روی generated column).
- **محل قوانین دسترسی:** همه‌ی قوانین در `app/Services/SheetAccess.php` هستند.

## ورود بدون ثبت‌نام

- **لینک دعوت:** مدیر از صفحه‌ی «اعضا و دسترسی» نفر را با نام، موقعیت شغلی (اختیاری، مثل «مدیر داخلی پروژه»)، موبایل، نقش و محدوده دعوت می‌کند و یک لینک دعوت می‌گیرد.
- **موقعیت شغلی:** کنار نام در فهرست اعضا، امضاهای تایید، یادداشت‌ها، چاپ و خروجی اکسل نمایش داده می‌شود.
- **ارسال لینک:** اگر `KAVENEGAR_SENDER` تنظیم شده باشد، لینک با پیامک هم فرستاده می‌شود.
- **ورود:** لینک فقط شماره را پر می‌کند. ورود همیشه با کد یکبارمصرفی است که به همان شماره پیامک می‌شود، پس لینک فورواردشده به‌تنهایی دسترسی نمی‌دهد.
- **رمز عبور:** در سامانه رمز عبوری وجود ندارد.

## انتشار و به‌روزرسانی

- **راهنمای هاست اشتراکی:** [docs/deploy-shared-hosting.md](docs/deploy-shared-hosting.md)
  - ساختار `core` کنار `public_html` است و `index.php` بدون ویرایش کار می‌کند.
  - راهنما شامل `.env` production، انتقال دیتابیس و عیب‌یابی است.
- **بسته‌ی نصب:** با Publish شدن هر Release در GitHub، workflow «Release package» بسته‌ی `tukahr-<نسخه>.zip` را به همراه checksum به آن Release اضافه می‌کند. این بسته vendor، assetهای ساخته‌شده و اسکریپت‌های Livewire را دارد.
- **به‌روزرسانی از داخل سامانه:** مدیر از صفحه‌ی «به‌روزرسانی» نسخه‌ی جدید را نصب می‌کند. مراحل: دانلود و بررسی، بکاپ دیتابیس، جایگزینی فایل‌ها، migration. اگر مرحله‌ای خطا بدهد، امکان بازگشت به نسخه‌ی قبل وجود دارد.
  - کد این بخش در `app/Services/Update` است.

## نصب محلی

```bash
cp .env.example .env
composer install
npm install && npm run build
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

با `TUKA_TEST_ADMIN_ENABLED=true`، دستور seed کاربران و یک لیست حقوق نمونه می‌سازد (فقط خارج از production):

| موبایل | نقش |
|---|---|
| 09120000000 | مدیر |
| 09120000001 | ویرایشگر دماوند |
| 09120000002 | تاییدکننده دماوند |
| 09120000003 | تاییدکننده همه پروژه‌ها (مالی) |
| 09120000004 | مشاهده همه پروژه‌ها (مدیرعامل) |

وقتی `KAVENEGAR_API_KEY` خالی باشد و محیط production نباشد، کد ورود در `storage/logs/laravel.log` نوشته می‌شود. در production، کلید خالی خطا می‌دهد.

برای ساخت اولین مدیر در production، `TUKA_ADMIN_NAME` و `TUKA_ADMIN_MOBILE` را تنظیم کنید و `php artisan db:seed --force` بزنید.

## کاوه‌نگار

در پنل کاوه‌نگار دو الگوی Verify Lookup بسازید، هر کدام با یک توکن `%token%`:

- `KAVENEGAR_OTP_TEMPLATE` (پیش‌فرض `tukahr-login`): کد ورود
- `KAVENEGAR_APPROVAL_TEMPLATE` (پیش‌فرض `tukahr-approval`): کد تایید و امضای لیست

تنظیمات کد: `OTP_TTL_SECONDS` (۱۲۰)، `OTP_MAX_ATTEMPTS` (۵)، `OTP_RESEND_SECONDS` (۶۰). کدها هش‌شده ذخیره می‌شوند.

## اکسل و PDF

- **ورود از اکسل (فقط مدیر، XLSX/CSV):**
  - سطر اول عنوان ستون‌هاست. `نام`، `نام خانوادگی` و `کد ملی` الزامی‌اند؛ `کد پرسنلی` و `پروژه` اختیاری.
  - بقیه‌ی ستون‌ها با ستون هم‌نام در لیست حقوق پر می‌شوند یا ستون تازه می‌سازند.
  - ورود همه‌یا‌هیچ است: اگر حتی یک سطر خطا داشته باشد، هیچ ردیفی ثبت نمی‌شود و همه‌ی خطاها گزارش می‌شوند.
- **خروجی اکسل:** RTL با سطر عنوان ثابت، به‌علاوه‌ی برگه‌ی «تاییدها». فقط ردیف‌هایی که کاربر اجازه‌ی دیدنشان را دارد خروجی گرفته می‌شوند.
- **PDF:** صفحه‌ی چاپ (A3 افقی) را با Save as PDF مرورگر ذخیره کنید. فارسی در این روش بدون مشکل رندر می‌شود.

## تست

```bash
php artisan test
```

- **پایگاه داده:** به‌طور پیش‌فرض SQLite در حافظه. CI همین تست‌ها را روی MySQL 8.4 و PHP 8.4 اجرا می‌کند (`.github/workflows/ci.yml`).
- **پوشش:** قوانین دسترسی، ذخیره‌ی خانه‌ها با کنترل نسخه، بازه‌ی مجاز ستون‌ها، ترتیب ستون‌ها، به‌روزرسانی (دانلود، checksum، جایگزینی و بازگشت) و بکاپ/بازگردانی دیتابیس روی MySQL، زنجیره‌ی تایید و hash، رد رکورد، یادداشت و حذف آن، ورود با OTP، دعوت و موقعیت شغلی، قید یک تاییدکننده برای هر پروژه، ورود اکسل و صفحات.

## نکته درباره شاخه‌ها

- **شاخه‌ی `develop`:** نسخه‌ی قبلی (طراحی شش‌نقشی و بدون Livewire) در آن است.
- **workflow `bootstrap-source.yml` و پوشه‌ی `.bootstrap/`:** همان نسخه‌ی قدیمی را از یک آرشیو باز می‌کنند و روی `develop` کامیت می‌کنند.
- **پیشنهاد:** بعد از ادغام این نسخه، آن workflow و پوشه را حذف کنید تا کسی به‌اشتباه نسخه‌ی قدیمی را روی کد جدید باز نکند.
